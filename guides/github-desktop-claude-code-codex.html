PHẦN 2. Đăng ký, đăng nhập GitHub

Bước 1 — Tạo tài khoản

  1. Mở trang github.com/signup.
  2. Nhập email hoặc chọn phương thức đăng ký được cung cấp.
  3. Thiết lập username (ví dụ nguyenvana-dev), mật khẩu và xác minh theo hướng dẫn.
  4. Mở hộp thư và xác nhận email GitHub.

Bước 2 — Đăng nhập

  1. Truy cập github.com/login.
  2. Đăng nhập theo phương thức đã tạo tài khoản.
  3. Hoàn thành xác thực bổ sung nếu hệ thống yêu cầu.

Bước 3 — Thiết lập bảo mật

Trong GitHub, mở Settings → Password and authentication và kích hoạt 2FA. Lưu phương thức khôi phục ở nơi an toàn.

Bước 4 — Hiểu Public và Private

  • Public: mọi người trên Internet có thể xem nội dung repo.
  • Private: chỉ những tài khoản được cấp quyền mới truy cập.
Với dự án công ty hoặc chưa được phép công bố, chọn Private. Private không có nghĩa là được phép tải mọi dữ liệu nội bộ lên dịch vụ bên ngoài.

PHẦN 3. Cài đặt và đăng nhập GitHub Desktop

Bước 1 — Tải phần mềm

Truy cập desktop.github.com, tải bản Windows, chạy file cài đặt và mở GitHub Desktop. Ứng dụng tích hợp Git đủ để thực hiện các tác vụ Git bên trong GitHub Desktop.

Bước 2 — Đăng nhập

  1. Chọn Sign in to GitHub.com.
  2. Trình duyệt hiện trang xác thực: đăng nhập và cho phép kết nối.
  3. Cho phép trình duyệt mở GitHub Desktop khi được hỏi.
  4. Nếu đã bỏ qua bước này, mở File → Options → Accounts → Sign Into GitHub.com.

Bước 3 — Tên người commit

Mở File → Options → Git, kiểm tra Name và Email dùng để ghi nhận tác giả commit. Email có thể là địa chỉ GitHub noreply phù hợp với tài khoản của bạn.

Kết quả: GitHub Desktop đã nhận tài khoản GitHub và bạn có thể tạo hoặc tải repository về máy.

PHẦN 4. Kết nối dự án trên máy với GitHub

Chọn đúng trường hợp để xem các bước phù hợp:

A. Đưa thư mục có sẵn lên GitHub

Ví dụ thư mục đang có là D:\Projects\INNO-Internal-Tool.

  1. Vào GitHub Desktop: File → Add Local Repository.
  2. Chọn đúng thư mục D:\Projects\INNO-Internal-Tool.
  3. Nếu có thông báo This directory does not appear to be a Git repository, chọn Create a Repository và kiểm tra đường dẫn khởi tạo để tránh tạo repo ở sai nơi.
  4. Kiểm tra file và thêm .gitignore nếu cần.
  5. Tạo commit đầu tiên với summary, ví dụ Initial commit - Upload project.
  6. Chọn Publish Repository, đặt tên và tích Keep this code private.
  7. Nhấn Publish Repository, rồi chọn Repository → View on GitHub để kiểm tra.
Nếu thư mục đã là repo kết nối remote khác, cần kiểm tra cấu hình remote và nhánh trước khi xuất bản.

B. Tạo dự án hoàn toàn mới

  1. Mở File → New Repository.
  2. Nhập tên my-first-project, chọn local path D:\Projects.
  3. Đánh dấu khởi tạo với README nếu có.
  4. Nhấn Create Repository.
  5. Nhấn Publish Repository, kiểm tra tùy chọn Private và hoàn tất.

Thư mục dự án được tạo tại D:\Projects\my-first-project.

C. Clone repo đã có trên GitHub

  1. Mở File → Clone Repository.
  2. Chọn tab GitHub.com để tìm repo hoặc URL để dán URL repository.
  3. Chọn đường dẫn lưu trên máy, chẳng hạn D:\Projects.
  4. Nhấn Clone và chờ quá trình tải xong.

Đối với repo Private, tài khoản GitHub của bạn cần có quyền truy cập.

Kiểm tra nội dung trước khi Push

Mã nguồn Node.js thường cần file .gitignore để tránh lưu dữ liệu tạm, thư viện đã tải và file môi trường. Ví dụ:

node_modules/
.env
.env.*
!.env.example
dist/
build/
*.log
.gitignore không xóa bí mật đã được commit trong quá khứ. Nếu lộ API key hoặc mật khẩu, cần thu hồi/đổi khóa và xử lý lịch sử repository theo chính sách bảo mật.

PHẦN 5. Đồng bộ bằng GitHub Desktop

5.1. Luồng chuẩn

Sửa file→Review Changes→Commit→Push origin

5.2. Ví dụ sau khi AI sửa trang đăng nhập

  1. Mở đúng repository trong GitHub Desktop.
  2. Vào Changes, xem những file được sửa, thêm hoặc xóa.
  3. Đọc từng diff để kiểm tra thay đổi có hợp lý không.
  4. Chạy thử dự án và kiểm tra chức năng (nếu dự án có thể chạy).
  5. Chọn những file muốn lưu trong commit.
  6. Nhập Summary, ví dụ Update login interface.
  7. Nhấn Commit to main (hoặc tên nhánh hiện tại).
  8. Nhấn Push origin và mở GitHub để xác nhận.

5.3. Dùng hai máy tính

💻 Máy công ty: Sửa → Commit → Push
↓
☁️ GitHub: nhận các commit
↓
💻 Laptop: Fetch → Pull → Sửa tiếp
Fetch tải thông tin trạng thái mới; Pull cập nhật nhánh local từ remote; Push gửi commit của máy lên remote. Trước khi bắt đầu làm việc trên máy mới, cần Pull đúng repo và nhánh.

PHẦN 6. Cài VS Code và mở dự án

  1. Truy cập code.visualstudio.com/download.
  2. Tải bản dành cho Windows, tiến hành cài đặt; nếu có tùy chọn Add to PATH nên bật.
  3. Trong VS Code, chọn File → Open Folder.
  4. Mở D:\Projects\INNO-Internal-Tool.
  5. Chỉ xác nhận tin cậy thư mục (Workspace Trust) nếu biết rõ nguồn gốc dự án.
  6. Chọn Terminal → New Terminal để mở nơi nhập lệnh.

Khi terminal hiển thị đường dẫn dạng PS D:\Projects\INNO-Internal-Tool>, nghĩa là bạn đang đứng trong đúng thư mục.

GitHub Desktop có thể có mục Repository → Open in Visual Studio Code nếu đã cấu hình VS Code làm trình chỉnh sửa mặc định.

PHẦN 7. Làm việc với Claude Code

7.1. Claude Code hoạt động ra sao?

Claude Code là AI Agent có thể đọc file, đề xuất thay đổi, sửa code và chạy lệnh trong môi trường được cấp quyền. Với cách sử dụng local, bạn không cần kết nối trực tiếp GitHub chỉ để Claude sửa dự án: mở Claude Code ngay trong thư mục mà GitHub Desktop quản lý.

7.2. Điều kiện

Cần Windows phù hợp, tài khoản có quyền dùng Claude Code và kết nối Internet. Quyền sử dụng/giới hạn tùy gói Claude hoặc Console. Xem quickstart chính thức.

7.3. Cài trên Windows

Cách A: Cài Claude Desktop, đăng nhập và chọn chức năng Code và thư mục dự án nếu tài khoản/phiên bản hỗ trợ.

Cách B: Cài Claude Code CLI bằng PowerShell:

winget install Anthropic.ClaudeCode

Hoặc sử dụng trình cài đặt native do Anthropic cung cấp:

irm https://claude.ai/install.ps1 | iex

Chỉ thực hiện các lệnh tải-chạy script khi đã xác minh chúng đến từ trang chính thức và được chính sách IT cho phép.

7.4. Khởi động trong đúng thư mục

cd "D:\Projects\INNO-Internal-Tool"
claude

Nếu cần kiểm tra đã cài hay chưa: claude --version. Lần đầu chạy claude, hoàn tất đăng nhập khi được yêu cầu.

7.5. Prompt đầu tiên: đọc dự án

Hãy đọc và phân tích cấu trúc dự án hiện tại. Giải thích bằng tiếng Việt dễ hiểu: dự án dùng công nghệ gì, chức năng từng thư mục, những file quan trọng, cách chạy dự án và các vấn đề cần lưu ý. Chỉ phân tích và báo cáo; chưa chỉnh sửa file nào.

7.6. Prompt chỉnh sửa có kiểm soát

Hãy cải thiện giao diện trang đăng nhập. Yêu cầu: hiện đại, rõ ràng, responsive; giữ nguyên cơ chế đăng nhập và chức năng đang hoạt động; không sửa module không liên quan; kiểm tra lỗi; tổng hợp danh sách file thay đổi. Trước khi sửa, hãy trình bày kế hoạch ngắn gọn để tôi xét duyệt.

7.7. Sau khi Claude hoàn thành

Mở GitHub Desktop cùng repo → Changes → kiểm tra diff → chạy thử → Commit → Push origin. Các file mà Claude sửa sẽ xuất hiện nếu thuộc repo và không bị Git bỏ qua.

PHẦN 8. Làm việc với OpenAI Codex

8.1. Các hình thức sử dụng

Codex có thể hoạt động qua CLI (terminal), extension trong trình chỉnh sửa mã nguồn, ứng dụng hoặc môi trường cloud. Để người mới dễ hình dung quy trình với GitHub Desktop, phần này ưu tiên cách làm việc local trên cùng thư mục dự án.

8.2. Cài Codex CLI trên Windows

Có thể dùng trình cài đặt chính thức trong PowerShell:

powershell -ExecutionPolicy ByPass -c "irm https://chatgpt.com/codex/install.ps1 | iex"

Hoặc, nếu đã cài Node.js/npm:

npm install -g @openai/codex

Kiểm tra bằng codex --version. Đối chiếu cách cài đang được hỗ trợ trên repository Codex chính thức.

8.3. Đăng nhập và khởi động

Trong PowerShell hoặc VS Code Terminal:

cd "D:\Projects\INNO-Internal-Tool"
codex

Lần đầu mở, chọn đăng nhập với ChatGPT nếu được cung cấp, hoàn tất xác thực trên trình duyệt. Quyền và giới hạn phụ thuộc gói dịch vụ đang sử dụng.

8.4. Dùng Codex Extension trong VS Code

  1. Mở VS Code → Extensions (Ctrl + Shift + X).
  2. Tìm Codex và xác minh nhà phát hành là OpenAI.
  3. Chọn Install, mở Codex và đăng nhập.
  4. Mở đúng project folder, gửi yêu cầu trong giao diện Codex.

Chi tiết: Codex IDE documentation.

8.5. Prompt tham khảo

Hãy phân tích dự án và tìm các vấn đề ảnh hưởng đến hiệu suất, khả năng bảo trì và trải nghiệm người dùng. Lập danh sách theo mức ưu tiên trước, chưa chỉnh sửa khi chưa có sự đồng ý của tôi. Sau khi tôi chọn một vấn đề, hãy thực hiện, kiểm tra và báo cáo các file đã thay đổi.

8.6. Codex Cloud khác gì Codex local?

Với Codex Cloud, AI có thể làm việc trong môi trường riêng kết nối với GitHub. Các thay đổi cần được review và chuyển về repo (ví dụ qua Pull Request), sau đó bạn mới Fetch/Pull về máy. Không nên giả định sửa ở cloud thì file trên máy tự cập nhật.

GitHub Repository
↕
Codex Cloud → thay đổi / Pull Request
↓ Sau review và merge
GitHub Desktop → Fetch / Pull về máy

PHẦN 9. Quy trình chuẩn làm việc hằng ngày

Sau khi đã cài công cụ, hằng ngày chỉ cần lặp lại các bước dưới đây.

Có thể dùng cả hai AI Agent?

Có. Nhưng không nên để Claude Code và Codex cùng lúc chỉnh sửa cùng một file trong cùng nhánh. Thay vào đó, giao lần lượt từng nhiệm vụ, review và commit giữa các lượt làm việc; hoặc tách branch/worktree nếu đã thành thạo.

Dùng branch khi thử nghiệm

  1. Trong GitHub Desktop, chọn Current Branch → New Branch.
  2. Đặt tên, ví dụ feature/new-login-ui.
  3. Để AI phát triển tính năng trên branch này.
  4. Review, Commit rồi Publish branch hoặc Push origin.
  5. Tạo Pull Request, review và merge vào main khi đạt yêu cầu.

PHẦN 10. Lỗi thường gặp và cách xử lý

GitHub Desktop không nhận thư mục dự án

Kiểm tra đúng thư mục gốc. Nếu chưa phải Git repository, chọn Create a Repository; không nên khởi tạo Git lồng vào thư mục sai hoặc trong repo đã có sẵn.

Đã sửa file nhưng tab Changes không hiện

Kiểm tra Current Repository, đường dẫn file và quy tắc .gitignore. Xác định xem thay đổi đã được commit chưa.

Đã Commit nhưng GitHub chưa có file mới

Commit lưu thay đổi trong lịch sử Git trên máy. Nhấn Push origin để chuyển commit lên GitHub và kiểm tra nhánh đang dùng.

Pull bị Conflict

Những phần thay đổi ở local và remote mâu thuẫn nhau. Dừng các thao tác tự động, xem file conflict và giải quyết cẩn thận. Sao lưu trước khi thực hiện lệnh ghi đè hoặc hủy thay đổi.

Lỗi “claude/codex is not recognized”

Đóng và mở terminal mới, thử kiểm tra phiên bản. Nếu vẫn lỗi, kiểm tra đã cài đúng, PATH của CLI hoặc xem lại tài liệu cài đặt tương ứng.

AI Agent không thấy dự án

Kiểm tra thư mục hiện hành của terminal (hoặc folder đang chọn trong giao diện). Chuyển đến đúng thư mục trước khi chạy lệnh claude/codex và kiểm tra các quyền truy cập.

AI sửa code nhưng chương trình bị lỗi

Kiểm tra Changes, xem lịch sử commit và đánh giá có thể revert hoặc discard file nào. Cảnh báo: discard có thể làm mất thay đổi chưa commit. Nên commit mốc ổn định trước các thay đổi lớn.

Hai máy không thấy cùng phiên bản

Máy thứ nhất phải Commit và Push; máy thứ hai phải Fetch/Pull trên cùng repo và nhánh. Các file chưa commit/push sẽ không tự chuyển qua GitHub.

PHẦN 11. Nguyên tắc bảo mật

  1. Không commit dữ liệu bí mật: mật khẩu, API key, token, file .env thật, dữ liệu khách hàng.
  2. Private repo không thay thế chính sách bảo mật: chỉ đưa dữ liệu công ty lên nền tảng bên ngoài khi đã được cho phép.
  3. Giới hạn quyền AI Agent: đọc kỹ trước khi cho phép chạy lệnh, xóa file, cài gói hoặc truy cập mạng.
  4. Review trước Commit/Push: đặc biệt khi AI tự sinh hoặc sửa nhiều file.
  5. Không coi GitHub là backup duy nhất: database, tài nguyên nhị phân và tài liệu cần chính sách backup riêng.
  6. Tránh lệnh Git phá hủy lịch sử: force push, reset --hard và xóa branch khi chưa hiểu rõ.
  7. Dự án công ty nên thuộc quyền sở hữu doanh nghiệp: ưu tiên GitHub Organization và phân quyền thích hợp.

PHẦN 12. Bài thực hành từ đầu đến cuối

Mục tiêu: tạo website cá nhân đơn giản bằng AI, lưu repository Private và đồng bộ lên GitHub.

Prompt bài thực hành

Hãy xây dựng cho tôi một website giới thiệu cá nhân đơn giản bằng HTML, CSS và JavaScript thuần. Website gồm phần giới thiệu, kỹ năng, dự án và liên hệ. Giao diện hiện đại, màu sắc hài hòa, hiển thị tốt trên máy tính và điện thoại. Hãy tạo các file cần thiết trong thư mục dự án hiện tại, không dùng thư viện ngoài và hướng dẫn tôi cách mở website để xem kết quả. Không sửa file nằm ngoài thư mục dự án.
